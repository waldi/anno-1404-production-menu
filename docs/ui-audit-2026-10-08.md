# Production dialog UI review — 2026-10-08

Evidence: fresh capture of the running dialog, 1440x1080 client viewport:
`../Anno 1404 Gold Edition/ui-audit-2026-10-08-01_full.png`.
Reviewed single-selection display; multi-selection interaction, keyboard focus,
hover tooltips, long names, scrolling and other resolutions were not exercised.

1. Open dialog / identify scope — needs improvement. Selected settlement has
   native gold artwork and the title names it, but the small title blends into
   the underlying HUD. Enlarge the title and place the selected settlement/count
   immediately beneath it. Add an explicit selected marker; color alone is weak.
2. Identify goods / compare figures — needs improvement. Internal names such as
   SaltFish, repeated Need/Produced labels and variable text positions require
   reading each sentence. Replace with native product icon + localized name,
   aligned numeric columns and a short status phrase. Keep names with icons.
3. Decide what needs attention — needs improvement. Amber/green names provide
   some signal, but no explicit shortage explanation. Put rows missing estimated
   capacity first; pair color with Missing capacity / Capacity available / Unknown.
   Do not claim actual surplus from counts of active buildings.

Highest-impact changes:
- Use a quieter, more opaque native background behind data. Visible forest and
  HUD compete with small text and make contrast depend on the camera position.
- Increase title and row hierarchy. Use roughly 40–48px rows with 28–32px native
  goods icons, plain readable names, subtle separators and aligned numbers.
- Label existing quantities truthfully: Estimated producers needed, Buildings,
  Active. Source production_lines currently compares population/200 or /340
  with active building counts, not measured output in tons/minute. Explain the
  estimate in help/tooltip. Use actual rates only after adding appropriate data.
- For the main calculator, a future rate table could use Demand (t/min),
  Nominal output (t/min), Difference and status, with actual delivered output
  clearly separate. Warehouse saturation can stop delivery despite capacity.
- Give selected scope prominence; show selected settlement chips or count for
  multiselection, and show the Ctrl-click hint once rather than twice.
- Use the available fullscreen area for a readable table, not larger empty
  background. At high row counts, prefer a scrollable list over narrow columns
  that make settlement names hard to recognize. Show all goods or expose a
  visible continuation: source currently limits displayed goods to 12.

Native icon implementation path: existing GUI supports LABEL ICONGUID and
ICONSTRETCH, plus inline icons. Use one fixed-size label per goods row and map
ware IDs to verified native icon GUIDs. Keep names visible and avoid guessed
GUIDs. No icon mapping was verified in this audit.

Accessibility risks visible in capture: scenery-dependent contrast, tiny title,
color-only goods statuses and selection feedback. Keyboard navigation, focus
visibility, screen reader behavior and numerical contrast ratios untested.

Recommended order: clarify metric meanings; opaque table surface and columns;
native icons with names; explicit status and sorting; multiselection summary;
scrolling and keyboard verification.
